# Serilog.Sinks.Lognara

Библиотека для отправки событий Serilog в локальный Lognara-agent. Поддерживает .NET 8 и новее, Serilog 4.4+. Код приложения с `Log.Information(...)` или подключённым к Serilog `ILogger<T>` менять не требуется.

## Подключение

Установите пакет из NuGet.org. Для дискового буфера на Windows используйте версию 0.1.2 или новее:

```sh
dotnet add package Serilog.Sinks.Lognara
```

Для проверки ещё не опубликованных изменений подключайте `src/Serilog.Sinks.Lognara/Serilog.Sinks.Lognara.csproj` через `ProjectReference` либо собирайте локальный пакет:

```sh
dotnet pack Lognara-dotnet/src/Serilog.Sinks.Lognara -c Release -o Lognara-dotnet/artifacts
```

```csharp
using Serilog;

Log.Logger = new LoggerConfiguration()
    .Enrich.FromLogContext()
    .WriteTo.Lognara()
    .CreateLogger();

try
{
    Log.Information("Заказ {OrderId} сохранён за {Elapsed} мс", 42, 12.5);
    // Запуск приложения; ILogger<T> должен быть подключён к Serilog отдельно.
}
finally
{
    await Log.CloseAndFlushAsync();
}
```

Адрес по умолчанию: `http://127.0.0.1:7400/v1/logs`. Это localhost приложения; если агент в отдельном контейнере, задайте доступный ему адрес и настройте слушающий интерфейс агента. Токен relay библиотеке не нужен: он хранится у агента. `service`, `server`, `backend`, `environment` и `service_instance` задаются в конфигурации агента.

```csharp
.WriteTo.Lognara(
    requestUri: "http://127.0.0.1:7400/v1/logs",
    queueLimitBytes: 16 * 1024 * 1024,
    period: TimeSpan.FromSeconds(1),
    restrictedToMinimumLevel: Serilog.Events.LogEventLevel.Information)
```

Поддерживается `levelSwitch` для изменения минимального уровня во время работы. Другие sinks можно оставить параллельно. Не собирайте те же события ещё и через файловый или консольный источник агента, если не нужны дубликаты.

## Буфер на диске

По умолчанию очередь находится в памяти. Для сохранения очереди между запусками:

```csharp
.WriteTo.Lognara(bufferBaseFileName: "/var/lib/my-app/lognara/buffer")
```

Каталог должен быть доступен приложению для записи, находиться на постоянном volume и использоваться только одним экземпляром sink. Сохраняйте путь между перезапусками. Это отдельный буфер приложения, не каталог spool агента. При возвращении к очереди в памяти сначала дайте дисковому буферу доставить накопленное.

Дисковый режим использует `Serilog.Sinks.Http` с ротацией по размеру: до четырёх файлов примерно по 16 MiB, плюс служебные файлы. Последнее событие может немного превысить размер файла. При исчерпании числа файлов старые файлы удаляются, возможны потери. `queueLimitBytes` действует только в режиме памяти. Буфер приложения не даёт гарантии fsync для каждого вызова Serilog; durable-гарантия Lognara начинается после ответа агента `202`.

Форматтер пишет JSON без перевода строки; разделитель дисковых записей добавляет sink. В версии 0.1.1 на Windows возникали пустые строки из-за несовпадения LF и CRLF, и flush мог отправить только первое событие. Обновление исправляет новые записи, но не переписывает накопленные файлы. Если очередь уже застряла, остановите приложение и сохраните весь каталог буфера вместе со служебными файлами для отдельного восстановления; не удаляйте очередь и не редактируйте её при работающем sink.

## Формат и доставка

- `timestamp`: время события в UTC, RFC 3339; `level`: `trace/debug/info/warn/error/fatal`; `message`: отформатированное сообщение с invariant culture.
- `trace_id` и `span_id`: идентификаторы из события Serilog, если присутствуют.
- `exception`: полный `Exception.ToString()`, включая inner exception и доступный stack trace; relay сохраняет его в attributes.
- `attributes`: свойства Serilog с сохранением вложенных объектов, массивов, чисел, boolean и null. В частности, `Metrics` остаётся объектом для текущего контракта ServiceMetrics. Произвольные свойства не повышаются до канонических полей.

Сетевые запросы выполняются в фоне через `Serilog.Sinks.Http`. Тело — JSON-массив, `Content-Type: application/json; charset=utf-8`. Каждая пачка содержит до 100 событий, целевой размер 1 MiB без разделителей; событие ограничено 256 KiB в UTF-8. Служебные разделители укладываются в запас до лимита агента 2 MiB. Если в агенте уменьшены лимиты записи или ресурсов, он может отклонять и эти пачки.

Проверка очереди по умолчанию раз в секунду. Таймаут HTTP-запроса 5 секунд, перенаправления отключены. Неуспешные HTTP-ответы и сетевые ошибки оставляют пачку для повторной отправки с backoff. Все ответы 2xx считаются подтверждением; штатный агент возвращает `202`. Повтор после потери ответа может создать дубликаты. При завершении нужно закрыть logger: выполняется финальная попытка отправки. Это не бесконечное ожидание доступности агента.

При превышении лимита события оно отбрасывается. Очередь в памяти ограничена 16 MiB сериализованных событий, при заполнении новые события отбрасываются; отдельно могут удерживаться отправляемая пачка и временные объекты, это не жёсткая квота RSS. Без дискового буфера завершение или падение приложения может потерять недоставленную очередь. Форматирование события происходит в вызывающем потоке, запись в дисковый буфер тоже имеет стоимость I/O.

Ошибки и потери доступны через `Serilog.Debugging.SelfLog`; направляйте его отдельно от Serilog, например в `Console.Error`. Библиотека не заменяет диагностику агента.

## Проверки

```sh
dotnet restore Lognara-dotnet/tests/Serilog.Sinks.Lognara.Tests --locked-mode
dotnet test Lognara-dotnet/tests/Serilog.Sinks.Lognara.Tests -c Release --no-restore
dotnet pack Lognara-dotnet/src/Serilog.Sinks.Lognara -c Release --no-restore -o Lognara-dotnet/artifacts
```

Тесты используют настоящий HTTP-сервер на свободном loopback-порту и временный каталог дискового буфера. Проверяют формат, уровни, structured properties, trace/span, отправку и flush, byte limits, переполнение очереди, повтор точного тела после `400`/`503`/разрыва соединения и восстановление дисковой очереди новым logger. Полный запуск Rust agent → relay → core не входит в эти тесты.

## Сборка и публикация

`.github/workflows/ci.yml` собирает и тестирует пакет на GitHub runners Ubuntu 24.04 и Windows 2025 с .NET SDK 8. Зависимости восстанавливаются с `--locked-mode`. NuGet-пакет Ubuntu сохраняется как артефакт `serilog-nuget`; публикация использует именно этот артефакт после успешной проверки `CI passed`, включая обе ОС.

При push в `master`, затрагивающем .NET-проверки, пакет автоматически отправляется в NuGet.org. Уже существующая версия пропускается через `--skip-duplicate`: для выпуска обновления измените `<Version>` в `src/Serilog.Sinks.Lognara/Serilog.Sinks.Lognara.csproj`. PR, рабочие ветки, ручные проверки и релиз контейнеров не публикуют NuGet-пакеты.

Однократная настройка [Trusted Publishing](https://learn.microsoft.com/en-us/nuget/nuget-org/trusted-publishing):

1. В аккаунте владельца `li_is` на NuGet.org создайте политику с Repository Owner `Liis17`, Repository `Lognara`, Workflow File `ci.yml` (без пути) и Environment `nuget`.
2. Ограничьте политику пакетом `Serilog.Sinks.Lognara` и разрешите публикацию новых версий.
3. В GitHub Actions Variables репозитория задайте `NUGET_USER=li_is`. Environment `nuget` можно дополнительно ограничить веткой `master` в настройках GitHub.

Постоянный API-ключ не нужен: только job публикации получает `id-token: write`, а `NuGet/login@v1` обменивает GitHub OIDC-токен на временный ключ. Без настроенной политики или переменной публикация завершится ошибкой; результаты тестов и артефакт останутся доступны.
