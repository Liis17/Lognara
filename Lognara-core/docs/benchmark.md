# Нагрузочная проверка

Целевой стенд: 4 CPU / 8 GiB / локальный SSD, release build. Поток 10000 событий/с в течение 1800 секунд; события около 1 KiB. Одновременно поиск последних 15 минут каждую секунду и минутная гистограмма каждые пять секунд. Критерий свежести — p99 не больше двух секунд от HTTP ACK.

```sh
cargo build --release --locked --manifest-path Lognara-core/Cargo.toml --bin lognara-core --example load
python3 Lognara-core/scripts/benchmark.py --output /path/on/ssd/run-01 --seconds 1800 --rate 10000
```

Каталог `--output` должен отсутствовать. Стенд запускает отдельный core на loopback:17403, создаёт временные токены внутри процесса, сохраняет данные в `<output>/data`, после прогона посылает SIGTERM. Ничего не удаляет. `--port` меняет порт. Требуются Python 3, `ps`; при наличии `iostat` сохраняется общая дисковая активность хоста.

Для 30 минут понадобится около 18 млн событий. Перед запуском оставьте место под данные и резерв; объём зависит от содержимого. Пример `load` можно запустить на отдельной машине с `LOGNARA_BENCH_URL`, `LOGNARA_INGEST_TOKEN`, `LOGNARA_QUERY_TOKEN`, `LOGNARA_BENCH_SECONDS`, `LOGNARA_BENCH_RATE`, `LOGNARA_BENCH_BATCH_SIZE` (по умолчанию 1000), `LOGNARA_BENCH_REPORT`.

Артефакты:

- `latencies.json`: фактическая скорость, offered/accepted, ошибки, размеры, p50/p95/p99/max ACK, поиска, гистограммы и видимости.
- `resources.jsonl`: каждые пять секунд RSS/CPU процесса, занятое/свободное место, WAL и метрики core.
- `host.json`: ОС, CPU/RAM, revision и несекретные параметры запуска.
- `storage.json`: размер после graceful shutdown, остаток WAL, код завершения core.
- `server.log`, `client.log`, `iostat.log`: диагностические данные. `iostat` отражает весь хост, не только core; первый отчёт может быть усреднён с загрузки ОС.

Генератор посылает по 1000 событий каждые 100 мс и не скрывает отставание или отказы повторными отправками. В случайном attributes payload 700 букв, message содержит номер события. Около одного события в секунду проверяется через точный ID каждые 25 мс после ACK; время включает стоимость поискового запроса. Это выборочная клиентская оценка видимости, не измерение каждого события. При очереди проб больше 32 или невидимости дольше 10 секунд фиксируется ошибка. Устойчивость оценивается по фактической скорости, ошибкам и тренду WAL/RSS, а не только завершению процесса.

Для окончательной приёмки повторите прогон на целевом Linux-сервере без параллельных сборок, желательно с генератором на другом хосте. Локальный macOS-прогон не подтверждает характеристики 4 CPU / 8 GiB. [Результаты контрольной проверки](benchmark-results.md) содержат фактическое оборудование и ограничения измерения.
