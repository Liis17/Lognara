# Проверка реализации core v1

База сравнения: `96224a959bd444587bd122ff853683fb80a3612e`. Требования: утверждённый пользователем план Lognara Core v1; стандарты: корневой `AGENTS.md`. Две независимые проверки кода: правила репозитория и соответствие плану.

## Standards

1. Неиспользуемое уведомление `Journal::wake` при polling worker нарушало правило удаления собственного неиспользуемого кода. Удалено; материализатор использует ограниченное ожидание 20 мс.
2. Эвристика Duplicated Code: создание анализатора текста повторялось для записи и запроса. Вынесено в `index::text_analyzer()`, чтобы обе стороны использовали одинаковую Unicode-токенизацию.

Итого: одно нарушение правила и одна рекомендация, оба устранены. Открытых замечаний по этой оси нет.

## Spec

1. Требование «очереди ограничиваются байтами»: MessagePack-лимит не ограничивал дерево `Value`. Добавлена проверка до serde без аллокаций, бюджет модели и учёт capacity распаковки в admission. Relay делит пачки по той же оценке. Регрессия с массивом null проверяет превышение бюджета и успешный разбор всех разделённых частей.
2. Требование «413 для превышения размера»: транспортная ошибка чтения тела тоже получала 413. Теперь отдельно распознаётся `LengthLimitError`, сбой транспорта возвращает повторяемый 503. Оба случая проверяются HTTP-тестом.
3. Требование «одинаковые конкурентные запросы ожидают одну запись»: admission немедленно отклонял второй запрос. Добавлено ожидание до секунды, максимум 64 ожидающих запроса; восемь HTTP-повторов дают восемь ACK и одну запись WAL. При исчерпании ограниченной очереди остаётся 503.
4. Ограничение ресурсов: страница поиска могла содержать до 1000 произвольно больших полных событий. Добавлен общий бюджет модели/ответа, проверка перед разбором каждой строки, чтение выбранных Parquet-строк по одной. При превышении выдаётся 503 без частичной страницы. Проверены Arrow и Parquet; меньшая страница возвращает полный лог. Permit удерживается до сериализации ответа.

Итого: четыре замечания, наиболее существенные касались памяти и ошибочного окончательного отказа relay. Все исправлены и повторно проверены; открытых замечаний по этой оси нет.

## Границы проверки

Тесты проверяют контракт настоящего encoder/relay, WAL, subprocess-сбои до/после fsync и на границах Parquet/каталога/очистки, SIGKILL после ACK, завершение retention после сбоя, поиск/курсоры, аналитику, точность типов и ресурсные отказы. `cargo fmt --check` и `cargo clippy --all-targets --all-features -- -D warnings` проверяют форматирование и lint.

Сбои процесса не моделируют все варианты отказа SSD/контроллера и питания. Нагрузочная цель на 4 CPU / 8 GiB требует прогона на целевом оборудовании; локальные результаты описываются с фактическими параметрами в отчёте benchmark.
