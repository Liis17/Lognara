# Источники файлов и потоков

Parent: [[Agent/LognaraAgent]]

## Назначение и границы

Универсальные источники одной программы: file, stdout, stderr с text/NDJSON/multiline. HTTP-контракт остаётся прежним. Сборщики добавляют записи напрямую в Buffer, без localhost HTTP. Настройки и примеры: `Lognara-agent/docs/log-sources.md`, `Lognara-agent/examples/log-sources/`.

Исходники: `src/sources.rs`, `framing.rs`, `files.rs`, `process.rs`, `output.rs` внутри `Lognara-agent/`; происхождение в agent `wire.rs` и relay `agent_wire.rs`/`normalize.rs`. Карта: [[Agent/LognaraAgent-ProjectMap]].

## Конфигурация и ресурсный контракт

`LOGNARA_SOURCES_FILE` указывает JSON `{"sources":[...]}`; unknown fields и ошибки вызывают отказ старта. Sources: стабильный уникальный ASCII ID до 64 байт, type и format; file требует include, поддерживает exclude/start_at; text поддерживает multiline start_pattern/flush_timeout_ms (1000 по умолчанию). Пути абсолютные, glob только в basename, без рекурсии. Настройки читаются только на старте.

Лимиты: 32 источника с автоматически добавленными потоками, 256 файлов, 64 открытых лог-дескриптора; JSON 256 KiB, 64 шаблона на источник, путь/regex до 4096 байт. Размер regex ограничен; классы байтовых regex используют ASCII. Источники резервируют `6 MiB + 3 * max_record_bytes` внутри общего бюджета, default 12 MiB из 64 MiB; без источников диагностика резервирует 512 KiB. Все каналы ограничены числом и размером блоков. Резерв Console не удерживает Buffer или spool-lock при заблокированном writer.

## Разбор и происхождение

LF/CRLF удаляется, пустая строка сохраняется, invalid UTF-8 даёт Binary. NDJSON сохраняет исходное JSON-значение строки; invalid JSON даёт Text с диагностикой. Multiline начинается при совпадении regex; idle flush только на EOF без новых данных и незавершённой строки. Незавершённый хвост активного файла ждёт дописывания; EOF потока и quiet-ротация завершают хвост.

Фрагменты до min(max_record_bytes, 512 KiB), UTF-8 режется по границам символов. Origin: source, path либо stream, byte offset/end, fragment и continued. Диапазон включает исходные разделители. Фрагменты NDJSON становятся Text/Binary. Порядок сохраняется внутри файла/потока. Relay резервирует память для происхождения до attributes; payload и контракт core прежние. Отсутствующий origin пропускается при сериализации, старые wire/spool читаются.

## Durable позиции и ротация

Checkpoint `sources.checkpoint` находится в spool под существующей directory lock. Порядок: durable append группы → atomic checkpoint rename с fsync файла и каталога. Неоконченное событие не подтверждается; сохранённые фрагменты сохраняют Continuation. Ошибка checkpoint ставит сбор на паузу с повтором записи позиции; уже сохранённая группа не добавляется повторно в текущем процессе. Crash между шагами допускает повтор; повреждённый checkpoint фатален.

Каталоги опрашиваются раз в секунду; известные файлы раньше новых, read round robin. При 64 FD доступный по тому же dev/ino пути cache descriptor освобождается для остальных файлов. Неизвестный файл ждёт, доступ повторяется, ошибки scan не удаляют позиции. Обычные файлы и ссылки на них допустимы, устройства/FIFO/socket/stdout-links, архивы и собственный spool исключены. Один физический файл имеет одного владельца; конфликты диагностируются.

Начальные файлы по умолчанию читаются с начала, start_at=end действует при первичном scan; checkpoint имеет приоритет, новые файлы читаются с начала. Ротация: старый дескриптор дочитывается, после restart inode ищется среди несжатых соседей. Проверяются dev/ino и SHA-256 фиксированных префикса/хвоста; обнаруженное изменение/усечение сбрасывает позицию. Quiet-интервал старого файла 5 секунд. При 75% квоты spool или числа записей файлы ждут. Гарантии требуют сохранения исходных несжатых файлов; copytruncate/удаление/сжатие/перезапись ограничивают восстановление.

## Потоки и lifecycle

`run -- PROGRAM ARGS` добавляет stdout/stderr по умолчанию. Настройка потока заменяет default. Без run они запрещены. Программа запускается непосредственно, без shell, после проверки config/spool/checkpoint/HTTP и установки сигналов, с прежними cwd/env и без LOGNARA_RELAY_TOKEN. Серверный foreground без TTY, без автоперезапуска.

Каждый pipe читается отдельно блоками до 64 KiB, raw-очередь 8 блоков. Echo пишет через отдельные std threads, очередь 64×4 KiB; медленная консоль не блокирует pipe. При перегрузке или ошибке сбора отбрасываются неподтверждённые данные и сбрасывается накопленное событие; следующая оборванная строка пропускается до LF. Счётчики байтов, целых разобранных событий, фрагментов, разрывов/сырьевых блоков и потерь echo независимы, сырые потери не превращаются в приблизительное число событий. Они выводятся в диагностике и не персистентны; Batch.dropped остаётся 0.

TERM/INT/QUIT начинают остановку и пересылаются основному процессу, HUP/USR1/USR2 только пересылаются. Сбор продолжается до выхода; stop timeout 10 секунд завершает группу. После child exit pipe drain ограничен 2 секундами, независимый deadline завершает оставшихся потомков до ожидания disk workers, сборщики и начатые disk workers ожидаются, HTTP останавливается, sender делает финальную отправку. Child exit code сохраняется, сигнал даёт 128+signal, отсутствующая команда 127, permission denied 126. Docker использует init и stop_grace_period 30s, исходный entrypoint оборачивается с сохранением инициализации.

## Ключевые интерфейсы

| Метод | Назначение |
|---|---|
| `Sources::load(path: Option<&Path>, capture: bool): io::Result<Sources>` | Ограниченно читает JSON и добавляет default потоки в run. |
| `Sources::parse(bytes: &[u8], capture: bool): io::Result<Sources>` | Разбирает и проверяет определения. |
| `Sources::validate(capture: bool): io::Result<()>` | Проверяет типы, лимиты, glob и regex. |
| `Sources::reserved_bytes(max_record: usize): usize` | Возвращает дополнительный резерв источников. |
| `Framer::new(source: &Source, limit: usize, offset: u64, continuation: Option<Continuation>): io::Result<Framer>` | Создаёт bounded разбор с восстановленной позицией. |
| `Framer::feed(bytes: &[u8]): Vec<Framed>` | Разбирает очередную ограниченную порцию. |
| `Framer::idle(): Option<Framed>` | Завершает полное накопленное multiline на idle. |
| `Framer::finish_all(): Vec<Framed>` | Завершает EOF, включая хвост без LF. |
| `Console::echo(bytes: &[u8]): ()` | Неблокирующе копирует вывод с учётом потерь. |
| `Console::drain(): ()` | Ограниченно ждёт writer, не задерживая завершение бесконечно. |

## Решения и основания

- Один механизм форматов и доставки для приложений выбран в согласованном плане пользователя; приложение задаёт файлы/потоки и формат.
- Durable spool предшествует checkpoint, чтобы падение давало допустимые повторы, а не пропуски сохранённого файла.
- Для файлов backpressure сохраняет данные у источника, для pipe приоритет имеет освобождение stdout/stderr программы; поэтому потери явно учитываются. Echo и диагностика ограничены и независимы.
- Docker API, journald, syslog, CSV, архивы, внутренние базы и специальные парсеры исключены границами первой версии.
