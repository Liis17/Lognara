# Relay memory

Parent: [[Relay/LognaraRelay]]

## Admission и конфигурация

`memory.rs` разделяет резервы приёма, накопленных моделей и отправки. Конфигурация проверяет сумму `ingest_request_bytes * concurrency + max_buffer_bytes + sender_bytes` без переполнения. По умолчанию это 1024 + 256 + 512 = 1792 MiB; профиль рассчитан на процесс с 2 GiB, оставляя 256 MiB для runtime, транспорта и allocator.

Входной резерв: два сжатых тела по 64 MiB, буфер распаковки 256 MiB + 1, бюджет модели, 128 MiB для codec и 128 MiB запаса; сумма округляется вверх до 128 MiB. Резерв sender: `core_max_decoded_bytes + 2 * core_max_body_bytes + 128 MiB`.

После авторизации и проверки заголовков `ingest` без ожидания резервирует slot. Без него отвечает `503` и не читает тело. Чтение ограничено 64 MiB и 30 секундами: один Vec с фиксированной capacity, каждый DATA frame освобождается после копирования. Число мелких фрагментов не увеличивает контейнеры в памяти. Permit переносится в blocking-задачу: отмена ожидающего HTTP-запроса не освобождает память работающего декодера. При остановке `Resources::drain` ждёт завершения всех допущенных работников до остановки sender.

Минимальные `max_model_bytes` и `max_buffer_bytes` — 8192, чтобы конфигурация могла принять хотя бы короткую текстовую запись. Нулевые исходящие лимиты и невозможная сумма резервов также отклоняются при запуске.

| Метод | Назначение |
|---|---|
| `Resources::new(config: &Config): Arc<Resources>` | Создаёт slots и пул накопленных моделей. |
| `Resources::ready(): bool` | Проверяет доступность приёма. |
| `Resources::set_ready(ready: bool)` | Меняет доступность приёма. |
| `Resources::drain()` | Закрывает admission и ждёт работников. |
| `run_blocking(permit: OwnedSemaphorePermit, work: FnOnce): Result<T, JoinError>` | Удерживает permit до завершения blocking-работы. |
| `Pool::reserve(bytes: usize): Result<Reservation, ReserveError>` | Без ожидания резервирует байты; отличает TooLarge от Full. |
| `Reservation::drop()` | Возвращает резерв в пул. |
| `Config::validate_memory(): Result<(), ConfigError>` | Проверяет ресурсную конфигурацию, включая программно созданную. |
| `Config::ingest_request_bytes(): Option<usize>` | Считает фиксированный резерв приёма. |
| `Config::sender_bytes(): Option<usize>` | Считает отдельный резерв отправки. |

Бюджет ограничивает управляемые аллокации, а не гарантирует точный RSS. Профиль проверяется нагрузочным тестом.

## Модель и нормализация

`model_budget.rs` ведёт единый убывающий бюджет через разбор Batch и всех записей. Перед serde MessagePack сканируется без объектов: 128 байт на узел плюс string/bin. Распакованный буфер заранее выделяется с capacity `limit + 1`, без роста; окно zstd ограничено 32 MiB, глубина MessagePack — 64.

JSON проходит дополнительный serde visitor без дерева Value: 256 байт на значение/ключ, удвоенная длина строк, глубина 64. До прохода учитываются scratch escaped strings (два размера исходного JSON) и 4096 байт временных контейнеров на запись. Event и capacity будущего Vec учитываются до создания. Binary резервирует base64 `4 * ceil(n / 3)` и контейнеры до кодирования.

Syntax error JSON сохраняет исходную строку без копирования. Превышение бюджета/глубины возвращает `413`, а не fallback. Бюджет намеренно не возвращает консервативные временные начисления между записями, поэтому сумма нескольких маленьких записей тоже ограничена. Обработчик публикует события только после успешной нормализации всех записей.

| Метод | Назначение |
|---|---|
| `ModelBudget::new(bytes: usize): ModelBudget` | Создаёт бюджет модели. |
| `ModelBudget::charge(bytes: usize): Result<(), TooLarge>` | Списывает память до выделения объектов. |
| `ModelBudget::remaining(): usize` | Возвращает остаток. |
| `agent_wire::decode_with_budget(body: &[u8], limit: usize, budget: &mut ModelBudget): Result<Batch, DecodeError>` | Ограничивает распаковку и начисляет входную модель перед serde. |
| `normalize::event_with_budget(record: Record, budget: &mut ModelBudget): Result<Event, TooLarge>` | Проверяет объекты JSON/base64 до нормализации. |

Низкоуровневый `normalize::event` используется для уже доверенных записей и фикстур; HTTP-путь вызывает только вариант с бюджетом.

## Нормализованные модели и sender

`ingest` резервирует нормализованную модель по capacity строк, Event, attributes и вложенных Value до кодирования. Модель уничтожается до освобождения RAII-резерва. `BatchEncoder` держит одну модель и диапазоны; LimitedWriter не растёт сверх лимита. Все части пишутся по одной в временную группу [[Delivery/Spool]]. Ошибка отдельного события отменяет группу; `202` выдаётся после fsync файлов, каталога и публикации.

Подтверждённых моделей в RAM нет. Sender читает одну сохранённую часть, не перекодирует и удаляет только после core ACK. Чтение ограничено `sender_bytes - CODEC_WORKSPACE`; unreadable/oversized файлы сохраняются. Размер изменённого файла требует восстановления metadata при перезапуске. Дисковая квота никогда не вытесняет старые данные.

Индекс файлов ограничен 100000 элементами и лимитом событий; пути частей относительные. Его накладные расходы входят в запас runtime. Semaphore чтения sender удерживается blocking-работником при отмене ожидающего future; shutdown ждёт его завершения.

## Нагрузочная проверка RSS

Из корня репозитория:

```sh
python3 Lognara-relay/tests/check-memory-profile.py
```

Скрипт собирает отдельный ignored test `bounded_relay_memory_profile`, затем запускает его в новом процессе. RSS опрашивается раз в 20 ms; при превышении 2048 MiB процесс завершается и проверка падает. После завершения дополнительно проверяется kernel high-water mark, чтобы обнаружить пик между измерениями. Компиляция в измерение не входит. Можно передать путь уже собранного test executable и изменить порог через `--limit-mib`.

Нагрузка использует стандартный профиль памяти, 16 одновременных клиентов в четырёх раундах, 48 текстовых записей по 2 MiB, 30 binary-записей по 2 MiB с телом около 60 MiB, JSON с миллионом null, binary 120 MiB, Text чуть меньше 256 MiB и превышение распаковки 256 MiB. Core отвечает `503`; проверяются admission, ресурсные `413`, сохранение spool и shutdown. Производитель фикстур находится в том же процессе, поэтому измерение включает и его память.

На macOS arm64 в debug-профиле измерен пик 1672.4 MiB при пороге 2048 MiB: приняты 9 пачек, 60 конкурентных запросов получили `503`, 4 ресурсных случая — `413`, shutdown завершился. Это проверка RSS внешним монитором, не проверка жёсткой квоты контейнера. Для deployment тот же тест следует запускать в Linux cgroup/container с лимитом 2 GiB; локально Docker недоступен.

| Метод | Назначение |
|---|---|
| `bounded_relay_memory_profile()` | Проверяет поведение при большой конкурентной нагрузке и недоступном core. |
| `check-memory-profile.py::main(): int` | Собирает тест, контролирует его RSS и возвращает результат проверки. |

Повторный прогон текущей реализации: пик RSS 1617,5 MiB, accepted=9, admission=60, resource=4; обе проверки ниже 2048 MiB. Максимальный наблюдавшийся пик 1672,4 MiB.
