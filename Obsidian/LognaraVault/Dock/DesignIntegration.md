## Основные зависимости

Первый предложенный выпуск: общий дизайн → исторический поиск и корреляция trace → базовая аналитика. Полные показатели требуют count/text-aware histogram/percentiles в core. Паттерны требуют серверного конвейера и стабильной идентичности; проблемы добавляют persistent lifecycle. Мониторинг узлов требует идентичности и heartbeat agent → relay → core. Алерты требуют фонового evaluator и долговечной доставки в dock.

Текущий SSE ограничен окном/размером и не является полным источником агрегатов или алертов. Реестр подключений пока не связан с source-полями событий. Текущий trace API возвращает логи; длительности spans из него не следуют.

Решения пользователя: полный план с поэтапной реализацией; Trace сначала показывает связанные логи, полноценные spans реализуются отдельным этапом; первые каналы алертов — Telegram и Discord. Детали контрактов и граница первого выпуска остаются предложениями плана.
