# Контракт метрик Dock и Core

Пользовательская спецификация переносимого JSON, примеры и инструкция для агента хранятся в [metrics-guide.md](../Lognara-dock/web/public/metrics-guide.md). [JSON Schema](../Lognara-dock/web/public/metrics-schema.json), [пример](../Lognara-dock/web/public/metrics-example.json) и [набор nginx](../Lognara-dock/web/public/metrics-nginx.json) раздаются Dock как статические файлы.

## Серверная область

Определение уникально по `(server, service, name)`; создание и изменение требуют `server`. Правила проверяют сервер до регулярного выражения. Предпросмотр и запрос графика принимают необязательный `server`; UI всегда передаёт его вместе с `origin`. Фильтр применяется ко всем источникам: открытым точкам, Parquet и rollups.

`GET /v1/series?group_by=server` возвращает `metrics` с полем `server`, серверными `first_seen`/`last_seen`, окружениями и определением. Определение без точек также присутствует. Необязательные фильтры `server` и `service` при `group_by=server` ограничивают каталог до формирования ответа. Обычный `GET /v1/series` сохраняет прежнюю группировку. Запрос графика без сервера допускает объединение только при одинаковых эффективных `kind`, `aggregation`, `unit` всех серверов, включая серверы без ручных определений; иначе 400 с `error: server_required`.

`GET /v1/series/sources` возвращает `{"sources":[{"server":"...","service":"..."}]}`. Источники из истории и heartbeat сохраняются в SQLite; определения без накопленных точек также добавляют свои сервер/сервис в список. Текущие источники и серии открытого сегмента добавляются из снимка в памяти. Список не сканирует Parquet.

Dock проксирует query-маршруты через `/api/series*` с query-токеном. Определения, preview и импорт идут с admin-токеном. Браузеру нужна сессия, изменяющим запросам — свой Origin; токены остаются в Dock.

## Выборочные метаданные и избранное

`POST /v1/series/lookup` (query-токен), прокси `POST /api/series/lookup`, принимает `{"keys":[{"server":"a","service":"api","name":"requests","origin":"counter"}]}`. Возвращает прежний `{"metrics":[...]}` только для выбранных ключей; повторы объединяются, неизвестные ключи опускаются, пустой список даёт пустой ответ. `origin` различает `counter`, `gauge`, `rule`. Запрос не получает значения графика.

Общее для всех пользователей избранное хранится только в SQLite Dock, таблица `favorite_metrics`, уникальный ключ `(server,service,name,origin)`. `GET /api/series/favorites` возвращает `{"keys":[...]}`. `PUT` и `DELETE` того же маршрута принимают один ключ без обёртки, идемпотентно добавляют/удаляют его и возвращают 204. Нужны сессия и собственный Origin для изменений; избранное сохраняется после перезапуска, отдельного пользовательского владельца нет. Ключ может остаться после исчезновения метрики; UI показывает недоступную карточку с возможностью удалить избранное.

При открытии `/metrics` браузер читает ключи избранного и одним lookup получает только их метаданные; при пустом избранном Core не вызывается. Раздел остальных закрыт: после его раскрытия загружается лёгкий список источников, после раскрытия сервера и сервиса - только каталог этого сервиса. Состояние раскрытия живёт до ухода со страницы. Избранные карточки не дублируются среди остальных. Страница отдельной метрики также использует lookup одного ключа.

Миниграфики запрашиваются по видимости карточек, не более двух одновременно; одинаковые запросы переиспользуются. Сворачивание снимает потребителей, отменяет ненужные запросы и удаляет их из очереди. Обновление перечитывает избранное и только раскрытые каталоги. Единица измерения большого графика показана один раз над графиком с переносом, на оси остаются числа с автоматически подобранным полем слева.

## Проверка и применение импорта

`POST /v1/admin/series/import/check` и `/apply` имеют прокси `/api/series/import/check` и `/apply`.

Проверка принимает `server`, `service`, `bundle` из 1-1024 метрик. Ответ: `revision` (SHA-256 снимка определений), `metrics`, `errors: [{index,field,message}]`, `conflicts: [{index,existing}]`. `index` с нуля; `null` обозначает ошибку всего набора. Неверные корневые поля/версия возвращают 400. Для каждой пары сервер/сервис разрешено до 1024 определений с правилом, включая выключенные; определения без правила квоту не занимают. Предупреждение квоты учитывает предполагаемые создания и замену определений без правила; итоговая квота проверяется при применении с учётом выбранных действий.

Применение принимает те же поля плюс `revision` и массив `actions` в порядке метрик. Действия: `{"action":"create"}`, `{"action":"skip"}`, `{"action":"rename","name":"new.name"}`, `{"action":"replace"}`. Замена требует существующего определения и сохраняет его ID; переименование требует свободного имени. Повторяющиеся итоговые имена отклоняются.

Под общей блокировкой каталога проверяются revision, имена, regex и квоты; затем одна SQLite-транзакция сохраняет весь набор и публикуется новый RuleSet. Ошибка до commit не меняет определения. Устаревший revision или неразрешённый конфликт возвращает 409 `import_conflict`; Dock сохраняет этот код. Ответ успеха: `created`, `replaced`, `skipped`.

## Переход со старого каталога

Версия `catalog.sqlite` — 3. При первом запуске Core до готовности восстанавливает индекс источников из проекций колонок логов и метрик, учитывает heartbeat и ожидающие пачки WAL. Чтение ограничено пачками по 4096 строк; прогресс хранится по файлам, незавершённый файл безопасно читается повторно.

Общие определения копируются на известные серверы соответствующего сервиса. Определения, для которых сервер не найден, удаляются по принятому решению. Лимит 1024 правил на пару сервер/сервис проверяется до изменения определений: превышение останавливает запуск, сохраняя исходные определения для исправления и повторного запуска. Замена определений и отметка завершения атомарны.

Копии имеют разные ID настроек, но сохраняют `legacy_rule_id` для извлечения: исторические и новые cumulative-точки остаются одной серией на каждом сервере. Поле сохраняется при редактировании и замене через импорт. WAL, Parquet и rollups не переписываются. Перед обновлением сохранить резервную копию каталога данных; старый Core каталог версии 3 не открывает.
